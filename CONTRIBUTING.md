# Como contribuir

Obrigado pelo interesse no SQO. Como esta é uma proposta conceitual em estágio inicial, a prioridade é construir uma base verificável sem confundir intenção, modelo e resultado.

## Antes de propor uma mudança

- Consulte o [estado do projeto](docs/PROJECT_STATUS.md) e a [visão técnica](docs/technical-overview.md).
- Abra uma issue para discutir mudanças de escopo, requisitos, interfaces ou dependências externas.
- Não publique material proprietário, classificado, sujeito a controle de exportação ou sem autorização.

## Padrões para mudanças

1. Identifique claramente se cada afirmação é **hipótese**, **simulação**, **ensaio** ou **resultado medido**.
2. Para afirmações técnicas, inclua fonte primária, premissas, método, versão de ferramentas/dados e limitações.
3. Não declare prontidão orbital, capacidade de armazenamento, vantagem quântica, integração operacional ou aprovação institucional sem evidência verificável.
4. Mantenha credenciais, tokens, chaves e dados pessoais fora de commits; use dados de teste não sensíveis.
5. Atualize o README, o estado do projeto e o PDF técnico quando uma alteração mudar o escopo documentado.
6. Prefira mudanças pequenas, rastreáveis e acompanhadas de testes ou procedimento reproduzível.

## Pull requests

Descreva o objetivo e o problema, liste as mudanças, identifique o tipo de evidência e declare limitações conhecidas. Se a alteração envolver um sistema externo, confirme que a interface e o uso estão autorizados e documente a fronteira de confiança.
